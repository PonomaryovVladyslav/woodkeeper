# Woodkeeper — принятые решения

> Этап 1: выбор технологий и архитектуры. Дата: 2026-10-16.

## Назначение

Личный сайт для планирования досок под улучшение мебели:

- вход через Google;
- 3–4 подпроекта, у каждого свой список досок;
- доска — параллелепипед с размерами длина × ширина × толщина в **миллиметрах**;
- добавление, редактирование, удаление досок;
- 3D-просмотр доски с вращением;
- для каждой из 6 сторон: облицована или нет, цвет облицовки (колор-пикер);
- количество одинаковых досок;
- отметка «заказана / не заказана».

## Требования к данным

| Сущность | Поля |
|---|---|
| Подпроект | название, описание |
| Доска | подпроект, название, длина / ширина / толщина (мм, целые), количество, заказана (да/нет), заметки |
| Сторона доски (6 шт.) | облицована (да/нет), цвет (HEX) |

Решения:

- **Количество** — поле у доски (одинаковые полки = одна запись).
- **Заказ** — отметка на всю позицию целиком; частичный заказ не нужен (при необходимости позиция делится на две).
- **Облицовка** — только цвет, без типа материала (магазин предлагает выбор только по цвету).
- **Ограничения размеров** — не нужны, размеры точные.
- **Сводки/отчёты** — не нужны.
- **Заметки** — текстовое поле у доски.
- **Порядок досок** — незаказанные сверху, затем по дате добавления; ручная сортировка не нужна.
- **Дублирование** — создание копии доски через редактор с предзаполненными полями.
- **Доступ** — ограничение только своим аккаунтом не требуется; данные всё равно привязаны к `user_id` из Google.
- **Стороны** доски по-столярному: 2 пласти (верх/низ), 2 кромки (длинные боковые), 2 торца.

## Технологический стек

### Фронтенд

| Что | Технология |
|---|---|
| Основа | React + TypeScript + Vite |
| UI-компоненты | Mantine |
| 3D | three.js через `@react-three/fiber` + `@react-three/drei` (`OrbitControls`) |
| Колор-пикер | `react-colorful` |
| Типы API | `openapi-typescript` — генерация TS-типов из OpenAPI-схемы FastAPI |

3D-модель: `BoxGeometry` с массивом из 6 материалов (по одному на грань). Облицованная сторона — выбранный цвет, базовая — нейтральный цвет. Модель нормализуется под размер окна, реальные размеры показываются подписями. Сторону можно выбрать кликом по модели или чекбоксом в форме (синхронно).

### Бэкенд

| Что | Технология |
|---|---|
| Язык | Python (основной язык автора, на нём же телеграм-бот) |
| Фреймворк | FastAPI + Pydantic v2, uvicorn |
| ORM | SQLAlchemy 2.0 |
| Миграции | Alembic |
| Зависимости | `uv` |

### База данных

**SQLite** — один файл в Docker volume. Для одного пользователя более чем достаточно, не требует отдельного процесса и памяти.

### Авторизация

1. Фронтенд: кнопка Google Identity Services → получает ID-токен.
2. Бэкенд: проверяет токен библиотекой `google-auth`, создаёт/находит пользователя.
3. Бэкенд выдаёт подписанную httpOnly-cookie с сессией.

## Инфраструктура

### Локальная разработка (текущий этап)

- Vite dev-server `localhost:5173`, проксирует `/api` → FastAPI `localhost:8000`.
- OAuth Client ID в Google Cloud Console с origin `http://localhost:5173`.

### Продакшен (после того как всё работает локально)

- Сервер: существующий AWS EC2 (t2/t3.micro), на нём же работает телеграм-бот.
- Docker Compose: `api` (FastAPI) + `caddy`.
- Caddy: раздаёт статику фронтенда, проксирует `/api`, автоматический HTTPS (Let's Encrypt).
- Домен — купить перед деплоем, добавить в authorized origins Google OAuth.

```
Интернет → Caddy (:443) ─┬─ /api/* → FastAPI (:8000) → SQLite (volume)
                          └─ /*     → статика React (dist/)
Телеграм-бот — независимо, как раньше
```

### Подготовка сервера

- [ ] Установить Docker + Compose plugin.
- [ ] Добавить swap 1–2 ГБ (на micro 1 ГБ RAM).
- [ ] Открыть порты 80/443 в Security Group.
- [ ] Проверить, что бот не занимает 80/443.
- [ ] Купить домен, направить A-запись на сервер.

Фронтенд собирается не на сервере (не хватит памяти), а локально или в GitHub Actions.

### Бэкапы

Ежедневная копия файла SQLite в S3 по cron (или непрерывно через Litestream).

## Рассмотренные и отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Supabase (Postgres + Auth) | Есть свой сервер; бесплатный проект засыпает после 7 дней неактивности |
| Firebase (Firestore) | Документная БД, для этой модели данных удобнее реляционная |
| Node.js + Fastify | Python лучше знаком автору — проще поддерживать |
| PostgreSQL | Избыточен для одного пользователя, занимает память на micro-инстансе |
