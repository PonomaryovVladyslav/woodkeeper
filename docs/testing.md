# Woodkeeper — план тестирования

> Этап 3: проектирование. Дата: 2026-10-16. Модель данных и API — см. [data-model.md](data-model.md).

## 1. Уровни и инструменты

| Уровень | Что проверяем | Инструменты |
|---|---|---|
| Бэкенд: unit | Схемы, валидация, маппер `faces` ↔ колонки, подпись cookie | pytest |
| Бэкенд: API | Все эндпоинты через HTTP, права доступа, БД | pytest + FastAPI `TestClient` (httpx) |
| Бэкенд: миграции | Alembic совпадает с моделями, upgrade/downgrade | pytest + Alembic API |
| Фронтенд: unit | Чистая логика в `lib/` | Vitest |
| Фронтенд: компоненты | Формы, списки, фильтры, подтверждения | Vitest + React Testing Library + MSW (мок API) |
| E2E | Ключевые сценарии в настоящем браузере на настоящем бэкенде | Playwright |
| Ручное | Реальный вход Google, 3D-взаимодействие, телефон | Чек-лист (раздел 6) |
| Статический анализ | Стиль, типы | ruff, mypy; tsc, ESLint |

Покрытие — ориентир, а не цель: бэкенд ~90%, фронтенд — вся логика в `lib/` и ключевые компоненты.

## 2. Тестовое окружение бэкенда

- **БД:** для каждого теста — отдельная SQLite во временном файле (`tmp_path`), создаётся через тот же `engine`-код, что в проде, чтобы срабатывали `PRAGMA foreign_keys=ON` и CHECK-ограничения. In-memory не используем — проще получить расхождение с продом.
- **Google:** `verify_google_token` подменяется через `app.dependency_overrides` / monkeypatch; возвращает заранее заданные `sub`, `email`, `name`. Сеть в тестах не используется.
- **Фикстуры** (`tests/conftest.py`):
  - `client` — неавторизованный клиент;
  - `user_client` — авторизованный пользователь A;
  - `other_client` — авторизованный пользователь B (для проверок чужого доступа);
  - `make_project(...)`, `make_board(...)` — простые функции-фабрики (без factory_boy).

Структура:

```
backend/tests/
  conftest.py
  test_schemas.py       валидация, нормализация цвета, маппер faces
  test_auth.py
  test_projects.py
  test_boards.py
  test_access.py        доступ к чужим данным
  test_db.py            PRAGMA, CHECK, каскады на уровне БД
  test_migrations.py
```

## 3. Тест-кейсы бэкенда

### 3.1 Схемы и маппер (`test_schemas.py`)

- [ ] `HexColor`: принимает `#a1b2c3`, `#A1B2C3` → нормализует в нижний регистр.
- [ ] `HexColor`: отклоняет `#fff`, `a1b2c3`, `#gggggg`, `red`, `#a1b2c3d`, пустую строку.
- [ ] `Faces`: все стороны по умолчанию `None`.
- [ ] Маппер: `Faces` → 6 колонок → `Faces` даёт исходный объект (roundtrip), в том числе все `None` и все заполненные.
- [ ] `BoardCreate`: значения по умолчанию — `quantity=1`, `is_ordered=False`, `notes=None`.
- [ ] Размеры: `0`, `-1`, `1.5`, `"abc"` → ошибка; `1` и большие значения (`100000`) → ок.
- [ ] `quantity`: `0` → ошибка, `1` → ок.
- [ ] `name`: пустое и > 100 символов → ошибка.
- [ ] `notes`: 2000 символов → ок, 2001 → ошибка.

### 3.2 Авторизация (`test_auth.py`)

- [ ] Валидный токен → 200, создаётся пользователь, ставится httpOnly-cookie.
- [ ] Повторный вход тем же `sub` → тот же пользователь, дубликата нет; email/name/avatar обновляются.
- [ ] Невалидный токен (верификатор бросает ошибку) → 401, cookie не ставится.
- [ ] `GET /api/auth/me` без cookie → 401; с cookie → текущий пользователь.
- [ ] Подделанная cookie (изменён payload/подпись) → 401.
- [ ] Просроченная cookie → 401.
- [ ] `POST /api/auth/logout` → cookie удалена, следующий `/me` → 401.
- [ ] Каждый защищённый эндпоинт без cookie → 401 (параметризованный тест по списку маршрутов).

### 3.3 Подпроекты (`test_projects.py`)

- [ ] Создание → 201, ответ содержит `boards_count=0`, `ordered_count=0`.
- [ ] Список возвращает только проекты текущего пользователя.
- [ ] PATCH только `name` — `description` не меняется, и наоборот.
- [ ] PATCH обновляет `updated_at`.
- [ ] Невалидное имя (пустое, > 100) → 422.
- [ ] Счётчики: 3 доски, 1 заказана → `boards_count=3`, `ordered_count=1`.
- [ ] DELETE → 204, проект и все его доски удалены из БД.

### 3.4 Доски (`test_boards.py`)

- [ ] Создание с минимальным набором полей → значения по умолчанию, все `faces` = `null`.
- [ ] Создание со всеми полями, включая `notes` и частично заполненные `faces`.
- [ ] Цвет в верхнем регистре сохраняется в нижнем.
- [ ] Список: незаказанные выше заказанных, внутри групп — по `created_at`.
- [ ] PATCH одного поля не трогает остальные.
- [ ] PATCH `faces` заменяет все 6 сторон (неуказанные стороны → `null`).
- [ ] PATCH `{is_ordered: true}` / `false` переключает статус.
- [ ] PATCH `notes: null` очищает заметки.
- [ ] PATCH `project_id` на свой другой проект → доска переносится.
- [ ] PATCH обновляет `updated_at`, не меняет `created_at`.
- [ ] Невалидные размеры / quantity / цвет → 422, данные в БД не изменились.
- [ ] DELETE → 204, доски нет в списке; повторный DELETE → 404.
- [ ] Несуществующие id проекта/доски → 404.

### 3.5 Доступ к чужим данным (`test_access.py`)

Пользователь B для объектов пользователя A получает **404** (не 403) на:

- [ ] `PATCH` / `DELETE /api/projects/{id}`;
- [ ] `GET` / `POST /api/projects/{id}/boards`;
- [ ] `PATCH` / `DELETE /api/boards/{id}`;
- [ ] `PATCH /api/boards/{свой_id}` с `project_id` чужого проекта (перенос в чужой проект запрещён);
- [ ] после всех попыток данные A не изменились.

### 3.6 БД (`test_db.py`)

- [ ] `PRAGMA foreign_keys` возвращает `1` на новом подключении.
- [ ] Прямая вставка с `quantity=0` / `length_mm=0` → `IntegrityError` (CHECK работает на уровне БД, а не только в Pydantic).
- [ ] Удаление проекта напрямую через сессию удаляет доски (каскад).
- [ ] Удаление пользователя удаляет его проекты и доски.

### 3.7 Миграции (`test_migrations.py`)

- [ ] `alembic upgrade head` на пустой БД проходит.
- [ ] После upgrade схема совпадает с моделями (аналог `alembic check` — нет непокрытых изменений).
- [ ] `downgrade base` → `upgrade head` проходит без ошибок.

## 4. Тесты фронтенда

### 4.1 Логика (`lib/*.test.ts`)

- [ ] `faces.ts`: порядок сторон соответствует материалам `BoxGeometry` (`right, left, top, bottom, front, back`); индекс грани → код стороны и обратно.
- [ ] Форматирование размеров: `1200 × 300 × 18 мм`, количество `× 4` (при 1 не показывается).
- [ ] Предзаполнение для дублирования: имя + « (копия)», `is_ordered=false`, нет `id`, остальные поля и `faces` скопированы.
- [ ] «Последний использованный цвет»: при включении стороны подставляется последний выбранный цвет; если его нет — цвет по умолчанию.
- [ ] Нормализация размеров модели для 3D: самая длинная сторона → фиксированный размер сцены, пропорции сохраняются.

### 4.2 Компоненты (React Testing Library + MSW)

`BoardPreview3D` в jsdom не рендерится (нет WebGL) — в компонентных тестах подменяется заглушкой; его логика покрыта через `lib/` и E2E/ручные проверки.

- [ ] `BoardEditor`: пустые/нулевые размеры → сообщения об ошибках, запрос не отправляется.
- [ ] `BoardEditor`: создание отправляет корректный JSON (числа, `faces`, `notes`).
- [ ] `BoardEditor`: в режиме редактирования поля заполнены данными доски, сохранение → PATCH.
- [ ] `BoardEditor`: в режиме дублирования поля заполнены копией, сохранение → POST.
- [ ] `FacesEditor`: чекбокс включает сторону и показывает выбор цвета; выключение → `null`.
- [ ] `BoardCard`: показывает размеры, количество, заметки; чекбокс «заказана» → PATCH.
- [ ] `BoardCard`: удаление требует подтверждения; отмена — запроса нет.
- [ ] `BoardList`: фильтры «все / не заказаны / заказаны»; пустое состояние.
- [ ] `ProjectTabs`: создание, переименование, удаление с подтверждением (текст предупреждает о досках).
- [ ] Ответ API 401 → переход на `/login`.
- [ ] Ошибка API 422/500 → сообщение пользователю, форма не закрывается.

## 5. E2E (Playwright)

### Вход в тестах

Реальный Google-вход автоматизировать нельзя. В бэкенде есть эндпоинт `POST /api/auth/test-login`, который регистрируется **только при `APP_ENV=test`**. Отдельный backend-тест проверяет, что при `APP_ENV=production` маршрута не существует (404).

### Окружение

Playwright поднимает бэкенд (`APP_ENV=test`, пустая временная SQLite) и собранный фронтенд.

### Сценарии

- [ ] **Основной путь:** вход → создать подпроект → добавить доску (размеры, количество, 2 облицованные стороны с цветом, заметка) → доска в списке → перезагрузка страницы → данные на месте.
- [ ] **Редактирование:** изменить размеры и цвет стороны → изменения видны в карточке.
- [ ] **Дублирование:** дублировать → поменять длину → сохранить → в списке две доски, у копии новая длина и «(копия)».
- [ ] **Заказ:** отметить «заказана» → доска уходит вниз списка → фильтр «не заказаны» её скрывает.
- [ ] **Удаление:** доски и подпроекта с подтверждением.
- [ ] **3D-смоук:** редактор открывается, `<canvas>` отрисован, нет ошибок в консоли.
- [ ] **Выход:** после выхода `/` перенаправляет на `/login`.

## 6. Ручной чек-лист

Перед первым деплоем и после крупных изменений.

**Вход**
- [ ] Реальный Google-вход локально (`localhost:5173`).
- [ ] Реальный Google-вход на домене по HTTPS.

**3D**
- [ ] Вращение мышью, зум колёсиком.
- [ ] Вращение и зум пальцами на телефоне.
- [ ] Клик по грани переключает облицовку именно той стороны, по которой кликнули (проверить все 6).
- [ ] Чекбокс в форме и подсветка на модели синхронны.
- [ ] Экстремальные пропорции: `2000×20×18`, `300×300×18`, `18×18×18` — модель видна целиком, не «нитка».
- [ ] Цвет на модели совпадает с выбранным в пикере.

**Интерфейс**
- [ ] Колор-пикер удобен на телефоне.
- [ ] Ширина ~400 px: формы и список не вылезают за экран.
- [ ] Длинные названия и заметки не ломают карточку.

## 7. Проверки после деплоя (смоук на сервере)

- [ ] HTTPS-сертификат валиден, HTTP перенаправляет на HTTPS.
- [ ] `GET /api/auth/me` без cookie → 401.
- [ ] `POST /api/auth/test-login` → 404 (тестовый вход в проде выключен).
- [ ] Вход через Google и создание тестовой доски.
- [ ] Перезапуск контейнеров (`docker compose restart`) → данные на месте (volume работает).
- [ ] Телеграм-бот продолжает работать.
- [ ] **Восстановление бэкапа:** скачать копию SQLite из S3, открыть локально, данные читаются. Бэкап, который ни разу не восстанавливали, бэкапом не считается.

## 8. CI (GitHub Actions)

На каждый push и pull request:

| Job | Шаги |
|---|---|
| backend | `uv sync` → `ruff check` → `ruff format --check` → `mypy` → `pytest --cov` |
| frontend | `npm ci` → `tsc --noEmit` → `eslint` → `vitest run` → `vite build` |
| api-types | Сгенерировать OpenAPI из FastAPI → `openapi-typescript` → `git diff --exit-code` (TS-типы не устарели) |
| e2e | Playwright (после backend и frontend) |

## 9. Порядок внедрения

Тесты пишутся вместе с кодом соответствующей части, а не в конце:

1. Бэкенд: схемы и маппер → `test_schemas.py`.
2. Модели, миграция → `test_db.py`, `test_migrations.py`.
3. Авторизация → `test_auth.py`.
4. Эндпоинты → `test_projects.py`, `test_boards.py`, `test_access.py`.
5. CI для бэкенда.
6. Фронтенд: `lib/` → unit-тесты; компоненты → компонентные тесты.
7. CI для фронтенда и проверка типов API.
8. E2E-сценарии.
9. Ручной чек-лист → деплой → смоук на сервере.
